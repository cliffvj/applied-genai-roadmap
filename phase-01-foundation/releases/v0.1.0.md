# Applied GenAI Foundation v0.1.0

`v0.1.0` is the first packaged release of the Applied GenAI Roadmap.

It completes Phase 1 by delivering a production-oriented Python and FastAPI foundation, asynchronous external model-service integration, strict automated quality controls, hardened container deployment, and GitHub-based CI and release automation.

## Highlights

### Reproducible Python Foundation

- Python 3.12.13 project environment
- uv-managed dependency locking and synchronization
- Hatchling source and wheel packaging
- Ruff formatting and linting
- Strict MyPy validation
- Pre-commit quality gates

### FastAPI and Pydantic Contracts

- Application factory and runtime configuration
- Strict request and response schemas
- Prompt validation
- Environment-based settings
- OpenAPI documentation
- Liveness and dependency-aware readiness

### Asynchronous Model-Service Integration

- Shared lifespan-managed asynchronous HTTP client
- Connection pooling
- Operation timeouts
- Bounded retries and exponential backoff
- Validated external health responses
- Validated prompt-generation responses
- HTTP 502 and HTTP 503 error mapping
- Deterministic mock model service

### Automated Testing

- Unit, integration, contract, and property-based tests
- Deterministic test factories
- Hypothesis-generated boundary testing
- Parallel execution through pytest-xdist
- Test and session timeout protection
- Statement and branch coverage
- Minimum 95% coverage requirement

### Hardened Containers

- Multi-stage production image
- Separate mock model-service image
- Non-root execution
- Read-only root filesystems
- Writable ephemeral `/tmp`
- Dropped Linux capabilities
- `no-new-privileges`
- CPU, memory, and PID limits
- Bounded log rotation
- Internal Compose DNS
- Health-based startup ordering
- Automated outage and recovery verification

### CI and Supply Chain

- Python CI for linting, typing, tests, and package builds
- Container CI for image builds, hardening, and recovery
- Dependabot coverage for Python, actions, and Docker
- CycloneDX SBOM generation from `uv.lock`
- SHA-256 release checksums
- GitHub provenance attestations
- Tag-driven release publication

## API Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/` | Return service metadata |
| `GET` | `/health/live` | Confirm process liveness |
| `GET` | `/health/ready` | Check dependency-aware readiness |

| `GET` | `/api/v1/model-service/status` | Check model-service availability |
| `POST` | `/api/v1/prompts/validate` | Validate a prompt request |
| `POST` | `/api/v1/prompts/generate` | Generate through the external model service |
| `GET` | `/docs` | Open Swagger UI when enabled |
| `GET` | `/redoc` | Open ReDoc when enabled |
| `GET` | `/openapi.json` | Return the OpenAPI schema |

## Verify Checksums

Download all release assets into one directory, then run:

```bash
sha256sum --check SHA256SUMS
```

Every listed asset should report:

```text
OK
```

## Verify GitHub Provenance

Using GitHub CLI:

```bash
gh attestation verify \
  applied_genai_foundation-0.1.0-py3-none-any.whl \
  --repo OWNER/REPOSITORY
```

Repeat the command for the source archive, container archives, SBOM, and checksum manifest.

A downloaded release asset can also be checked against the release:

```bash
gh release verify-asset \
  v0.1.0 \
  applied_genai_foundation-0.1.0-py3-none-any.whl
```

```bash

python -m pip install \
  applied_genai_foundation-0.1.0-py3-none-any.whl
```

```powershell

.venv\Scripts\Activate.ps1

python -m pip install `
  applied_genai_foundation-0.1.0-py3-none-any.whl
```

## Load the Production Container Archive

```bash
gunzip -c \
  applied-genai-foundation-0.1.0-linux-amd64.tar.gz \
  | docker load
```

Run the image:

```bash
docker run \
  --rm \
  --publish 127.0.0.1:8000:8000 \
  --env APPLIED_GENAI_MODEL_SERVICE_REQUIRED_FOR_READINESS=false \
  applied-genai-foundation:0.1.0
```

Verify liveness:

```bash
curl \
  http://127.0.0.1:8000/health/live
```

## Load the Mock Model-Service Archive

```bash
gunzip -c \
  applied-genai-mock-model-service-0.1.0-linux-amd64.tar.gz \
  | docker load
```

The normal two-service development workflow remains:

```bash
docker compose up \
  --detach \
  --wait \
  --wait-timeout 120
```

## Known Limitations

- Prompt generation is non-streaming.
- The included model service is a deterministic simulator.
- Container archives target Linux AMD64 only.
- Images are not yet published to a container registry.
- Authentication, authorization, TLS termination, and external secret management are not yet implemented.
- GPU device assignment and NVIDIA Container Toolkit support are reserved for later phases.
- Production metrics, tracing, and centralized logging are future work.

## Next Phase

The next phase will expand from the application foundation toward practical Applied GenAI infrastructure, model serving, retrieval, Linux/GPU operations, deployment automation, observability, and security engineering.
